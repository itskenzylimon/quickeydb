# Test map

Tests are arranged by feature so a behavior has an obvious regression home.
Common temporary-database fixtures and generated DAO source live in `support/`.
The fixture source is generated by the public API and analyzed alongside tests.

| Folder | Key functions and contracts |
| --- | --- |
| `documentation/` | Standalone pub.dev example synchronization, canonical workflow keyset paging, transactional replacement/rollback and scoped bulk updates |
| `codegen/` | Multi-table SQL splitting, comments/quotes, safe Dart source, names, invalid inputs, registration, generated DAO CRUD and foreign keys |
| `crud/` | Insert/create, generated IDs, conversion, update/delete, conflict policies and explicit scoped deletion |
| `diagnostics/` | CRUD SQL events, redaction, opt-in controls and observer failure isolation |
| `queries/` | Independent scopes, bound values, nulls, OR/NOT, aggregates, projections and redacted diagnostics |
| `transactions/` | Atomic bulk writes, rollback, transaction executor and 1,000-record correctness |
| `relations/` | HasMany/HasOne/BelongsTo loading, joins, includes and nested write rollback |
| `schema/` | Metadata parsing, nullable columns and unsupported composite keys |
| `storage/` | Legacy reopening, private paths, asset import and upgrade preservation/rollback |
| `security/` | AES contexts/nonces, key validation, tampering, legacy encryption migration and SQLCipher fail-closed behavior |
| `memory/` | Typed values, durability, namespace sharing/mismatch, TTL, migration, incremental persistence and close |
| `tooling/` | Narrow/idempotent backport of the upstream Flutter debug-loader fix |
| `support/` | Shared ORM fixture and compilable generated DAO fixture; no standalone tests |

From the package root:

```sh
flutter pub get
flutter analyze
flutter test
flutter test test/codegen
flutter test test/queries test/transactions
flutter test test/memory test/security
```

The same generator contract cases also run without a Flutter test runner or
native build hooks:

```sh
dart --packages=.dart_tool/package_config.json test/codegen/sql_generator_contract.dart
```

The standalone contract file is shared with `sql_dao_generator_test.dart`, so
checks are not maintained twice. It does not exercise SQLite integration.
`generated_dao_integration_test.dart` registers the generated Projects/Tasks
classes, performs CRUD and verifies foreign-key enforcement against real SQLite.

See [gallery test instructions](../example/README.md#tests-by-feature) for native
widget and Chrome worker/UI tests. Native hooks can require a working Apple SDK
even for a Chrome test run on macOS. If Xcode reports an unaccepted license,
complete Xcode setup locally and retry; analysis and a web build do not replace
the blocked tests. No tests accept license terms or alter system configuration.

The Activity-style example now has 19 sections. Its host gallery tests cover every
section at desktop and phone widths, actual encrypted pagination/aggregation,
rolled-back conflict and bulk probes, migration-plan safety, checklist and theme
changes. The separate Chrome worker suite repeats the new database probes. See
example/README.md for data effects and application-recipe boundaries.

The example also tests Activity-owned state, named section/deep links, typed note
results, draft retention, source API/View/Model tabs, live result terminals,
ASC/DESC/projection options and controller cleanup without closing the borrowed
database. The Chrome worker scenario covers the same source and routing UI.
